# Forensic audit: does Kling output carry a hidden watermark or provenance signal?

Date: 2026-10-09. Scope: Kling IMAGE 2.1 and IMAGE 3.0 PNGs and VIDEO 3.0 MP4s, generated by the author on three of their own accounts through kling.ai (international). Detection only: nothing here removes, forges or alters a label.

## A. Executive conclusion

| Signal | Verdict | Confidence |
|--------|---------|------------|
| Provenance **metadata** (`AIGC` label, GB 45438-2025) | **Detected** in every post-2025-09-01 image and video | High |
| In-bitstream video marker (H.264 SEI, text `kling-ai`) | **Detected** in the VIDEO 3.0 file | High (one sample) |
| Invisible **pixel watermark in images** | **Inconclusive.** Kling officially states one exists and runs a `BLIND_WATERMARK` detector, but none of our independent tests found it | Medium |
| C2PA / content credentials | **Not present** (no `caBX`/JUMBF/XMP in any Kling file) | High |

The previous project statement "there is no invisible pixel watermark" was too strong and is withdrawn. Our tests rule out common schemes (LSB, fixed additive patterns, block-DCT bias of meaningful size, SynthID, TrustMark, Watermark Anything, `invisible-watermark`) and any pattern in flat image regions. They cannot rule out a keyed, content-adaptive mark embedded only in textured regions.

## C. Strongest findings

1. **Kling officially claims a blind watermark.** The [AI Content Detection](https://kling.ai/docs/ai-content-detection) page says "an imperceptible watermark and metadata are embedded in images and videos", remaining traceable "through compression, editing, and resharing", and points to kling.ai/detection. The detector's own API names two detectors: `AIGC_METADATA` and `BLIND_WATERMARK`. This is the strongest evidence **for** a pixel-level mark, but it is a claim, not a measurement: the blind-watermark check failed on every file we submitted.
2. **Metadata labels are certain.** PNG `tEXt AIGC` and MP4 `AIGC` key, decoded fully (see FINDINGS.md).
3. **Video has a second, in-bitstream marker.** The H.264 SEI message with payload `kling-ai` lives inside the coded video, so it survives remuxing or stripping MP4 metadata (not re-encoding).
4. **Flat regions carry nothing.** In 48 of 105 near-uniform images, at least one channel is a single value across the whole interior. No pixel-domain mark exists there.

## D. Negative findings

- No LSB embedding, no appended data, no ICC profile, no EXIF, XMP or C2PA in Kling files.
- No fixed additive pattern shared across images at watermark scales (averaged residual at the noise floor).
- No meaningful block-DCT or wavelet-HH signature beyond shading and the 32 px grid.
- Four public watermark decoders found nothing (with working positive controls).

## E. Reproducibility

Environment: Python 3.14, Pillow 12.3, NumPy 2.5, SciPy 1.18 (plus `trustmark` and Meta `watermark-anything` for section 5 of FINDINGS). Samples are local (`samples/`, not in git).

```bash
python -m venv .venv && .venv/bin/pip install pillow numpy scipy
PYTHONPATH=src .venv/bin/python -m kling_label --json samples/round2/*.png samples/round2/*.mp4
.venv/bin/python forensics/audit.py container
.venv/bin/python forensics/audit.py steg
.venv/bin/python forensics/audit.py dct
.venv/bin/python forensics/audit.py wavelet
.venv/bin/python forensics/audit.py residual
.venv/bin/python forensics/audit.py bands
.venv/bin/python forensics/audit.py grid
.venv/bin/python forensics/audit.py robust
```

Plain-image generation: IMAGE 3.0, 2K, 9:16, reference image = flat grey PNG (values 64, 128 or 192), prompt "Exact copy of the reference image, solid flat uniform grey, nothing added".

Official detector test files: original Kling PNG; same pixels without metadata; JPEG q85; crop+resize; stripped Kling plain image; own flat grey; synthetic noise; Kling MP4.

## F. Limitations

- **Texture-masked marks.** Many blind watermarks are embedded only where texture hides them (JND masking). Plain images test flat regions only, and the 27 normal images are too few for a sensitive test on textured content.
- **Keyed marks.** A mark keyed per image or per user would not average across images; only the owner's detector can find it.
- **Official detector unavailable for images.** Every image submission returned `FAILED`, so Kling's own `BLIND_WATERMARK` result for images is unknown.
- One video sample; no mobile-app, mainland-China or paid watermark-free outputs.

### Samples that would settle the question

1. Kling's detector working on images: resubmit (a) an original, (b) the same pixels without metadata, (c) a JPEG q85 copy, (d) a never-generated control. If (b) or (c) is flagged by `BLIND_WATERMARK`, a pixel mark exists.
2. About 100 **textured** IMAGE 3.0 images (2K, 9:16, varied prompts) for a texture-weighted noise-residual test.
3. Several more videos (to confirm the SEI marker and test the video blind watermark).
