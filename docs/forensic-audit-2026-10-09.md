# Forensic audit: does Kling embed an invisible image watermark?

Version 2, 2026-10-09. Scope: Kling IMAGE 2.1 and IMAGE 3.0 PNGs and VIDEO 3.0 MP4s, generated by the author on three of their own accounts through kling.ai (international). Detection only: no step here removes, forges or alters a label in a published file.

## A. Executive conclusion

**Inconclusive because of detector limitations.**

- Kling **documents** an imperceptible watermark in images and videos, and its detector runs a check that its API names `BLIND_WATERMARK`.
- That check **never produced a result**: it returned `FAILED` on all 10 image submissions (including untouched originals) and on the one video.
- Independent methods found **no image watermark** beyond a periodic 8/16/32 px pipeline grid that also appears in non-Kling images. Those methods cannot exclude a per-image keyed or content-adaptive mark.

Confirmed signals: `AIGC` metadata in images and videos; an H.264 SEI marker `kling-ai` in the VIDEO 3.0 bitstream.

| File | Construction | Verified |

Condition D (visible label): Kling images carry a small visible "KlingAI" logo in the bottom-right corner. No test isolated it, because the detector never returned results for images.

**Official-detector outcome:** the lossless no-label copy returned `FAILED`, as did every original. No metadata-independence conclusion is possible yet.

## Phase 4 and 7: the official detector and `BLIND_WATERMARK`

Observed behaviour (all from the owner's logged-in session at kling.ai/detection):

| Submission | Files | Image results | Video result |
|------------|-------|---------------|--------------|
| Batch 1 | 7 images + 1 MP4 | 7/7 `FAILED` | `AIGC_METADATA`: Detected, producer Kling AI; `BLIND_WATERMARK`: `FAILED` |
| Batch 2 | 1 image (B, re-encoded no-label) | `FAILED`; `failReason: "AIGC_METADATA,BLIND_WATERMARK"` | - |
| Batch 3 | 1 image (A2, lossless no-label) | `FAILED` | - |

- **Where `BLIND_WATERMARK` comes from:** it is not in the public documentation. It appeared in the JSON response of the site's own task-detail request (`/api/creation/v4/detection/tasks/detail`), read from the owner's browser session: `"signals":[{"detector":"AIGC_METADATA",...},{"detector":"BLIND_WATERMARK",...}]`. The page labels the second row "Invisible watermark". So it is an **internal result code observed in a live response**, not a documented API.
- **What it proves:** Kling runs a separate check besides metadata. It does **not** prove that the check measures pixels, or that image outputs carry a mark. Evidence that would: a `Detected` result on a lossless no-label copy, while a never-generated control is `Not detected`.
- The capability endpoint reported image formats jpeg/jpg/png, a 50 MB image limit, 10 files per task, and a per-account quota (10, now 0 on account C).
- `FAILED` is an error state, not a negative result.

## Phase 5: candidate signal classes

| Method | Can detect | Cannot detect | Obscured by | Expected false positives | Is a negative meaningful? |
|--------|-----------|---------------|-------------|--------------------------|---------------------------|
| Leave-one-out residual correlation (fixed pattern) | Same additive pattern at the same positions in every image | Per-image or per-user keyed marks; content-adaptive marks | Cropping or shifting, strong denoising | Pipeline grids, shared shading | Yes, for a fixed global pattern |
| Plain-image flatness (105 images) | Any change to pixel values in flat regions | Marks that skip flat regions (JND-masked) | - | Generator shading, edge artifacts | Yes for flat regions; no for textured regions |
| Textured-region LOO (12 images) | A fixed pattern hidden only in busy areas | Keyed or per-image marks; weak marks (12 images is low power) | Shifting, heavy JPEG | The periodic grid (removed by notch) | Weakly |
| FFT band analysis | Periodic or narrow-band carriers | Spread-spectrum keyed marks below the noise | Resampling | Upscaler and VAE grids | Partly |
| Block-DCT bias | Consistent coefficient offsets on the 8x8 grid | Keyed sign patterns | JPEG recompression | Shading and 32 px grid alias into DCT positions | Weakly |
| Haar wavelet split-half | Shared subband patterns | Keyed marks | Blur, resampling | Grid and shading in LH/HL | Partly |
| Chi-square LSB, bit planes | LSB replacement or equalisation | Marks spread over higher bits | Any re-encode | Flat images (low LSB entropy) | Yes, for LSB schemes |
| TrustMark, Watermark Anything, invisible-watermark | Their own schemes | Any other scheme | Varies | Low (positive controls passed) | Only for those schemes |
| SynthID Detector | Google-partner SynthID | Non-partner schemes (Kling is not a partner) | - | Low | Only for SynthID |
| Container and SEI inspection | Metadata, appended data, bitstream user data | Pixel marks | Re-encoding | None | Yes, for container signals |

## Phase 6: robustness

The only shared signal found, the 32 px grid, survives JPEG q95 and q75, resizing, a 7 px crop, colour conversion, brightness and contrast changes, blur and sharpening. JPEG q50 destroys it. It is equally strong or stronger in non-Kling controls (median peak ratio 7.7 vs 1.9 to 5.3 for Kling), so it is not a usable identifier. The `AIGC` metadata does not survive a plain re-save.

## E. Technical findings with alternative explanations

| Finding | Measurement | Most likely explanation | Alternatives |
|---------|-------------|-------------------------|--------------|
| 32 px periodic grid | 81% of shared energy in the 0.02-0.05 cycles/px band | Block or patch generation at 1K (16 px) after a 2x upscale | Tiled upscaler, VAE stride |
| Large-scale shared shading | 93% of shared plain-image energy below 0.005 cycles/px | Generator prior or reference-image pipeline | Vignetting-like post-processing |
| PNG encoder fingerprint | Sub filter on every row, zlib fastest, 8 KB IDAT | Kling's server-side PNG writer | - (identifies the writer, not the content) |
| Edge artifacts in plain images | 32 px ragged border | VAE or padding boundary effects | Upscaler borders |

## G. Limitations and next experiments

- **Per-image keyed or content-adaptive marks** cannot be found by averaging-based tests; only the owner's detector can find them.
- **Low power in textured regions:** only 12 usable normal images of one size and model.
- **No working official result for images.**
- One video; no mobile-app, mainland-China, JPEG-download or paid watermark-free samples.

**Smallest decisive next experiment** (one batch of 4 on an account with detection quota, once image detection works):

1. A2 original (positive control).
2. A2 lossless no-label (IDAT byte-identical).
3. A never-generated image of similar content and size (negative control).
4. A2 no-label after JPEG q85 (tests the documented robustness).

If (1) and (2) return `BLIND_WATERMARK: Detected` and (3) does not, a pixel-level mark is confirmed independently of metadata. If (2) is negative while (1) is positive, the detector's image result depends on metadata.
